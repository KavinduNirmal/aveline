# Agent: Customer Memory Agent (Slice 1)

> **Owner:** Student 1  
> **Domain:** Customer Concierge & Memory

The **Customer Memory Agent ("Ava")** understands who the customer is and what they want, so
boutique associates are prepared for every interaction. It is a dependency-injected LangGraph
sub-graph (ADR-002) that orchestrates a thin `ToolRegistry` wrapper over the backend internal
endpoints.

## Responsibilities

1. Resolve/identify the customer (org + customer id **or** phone number).
2. Respect consent — a revoked customer short-circuits and nothing is retrieved or stored.
3. Parse inbound messages into structured intent (occasion, colour, size, budget), preferences
   and event signals.
4. Retrieve relevant semantic memories (pgvector via the backend).
5. Capture new preferences and **structured events**, and log each inbound interaction.
6. Produce a staff-facing interaction brief (built from the backend's real events/tags) plus a
   draft reply — optionally generated by an LLM, falling back to a deterministic template.

## Flow

```
resolve_customer → check_consent → parse → retrieve → persist → compose_output
```

- `resolve_customer` / `check_consent` short-circuit to END with a `skipped` status when there is
  no customer context or consent was revoked.
- `parse` always runs; `retrieve`/`persist`/`compose_output` need a resolved, consenting customer.
- `compose_output` validates the assembled result against `MemoryAgentOutput`
  (`app/schemas/customer_memory.py`) so contract drift fails loudly (Issue #167).

## Backend access

The agent talks to the backend **only** through `ToolRegistry` (`app/tools/registry.py`) — there
are no per-tool files in `app/tools/customer/` any more. The registry methods forward to the
`/internal/customers/*` endpoints (see `app/tools/customer/README.md`).

## What belongs in this folder

- `graph.py` — the LangGraph `StateGraph` (compiled by `build_memory_graph`).
- `state.py` — the typed `MemoryAgentState` schema.
- `nodes.py` — the node functions (incl. LLM draft generation + usage capture).
- `parsing.py` — deterministic rule-based intent/preference/event parsing.

## What does NOT belong here

- Backend tool wrappers (those live in `app/tools/registry.py`).
- Pydantic I/O schemas (those live in `app/schemas/customer_memory.py`).
- FastAPI routes (those live in `app/api/agents.py` under `/agents/query`).
