# `tests/performance` — Aveline web performance harnesses

These harnesses exist because the repository had **no recorded performance
baseline, no bundle budget, and no performance gate in CI** before this audit.
They produce the numbers cited in
`.agents/plans/web-performance-optimization-implementation.ignore.md` and they
are meant to be re-run after each optimization so every claim has a before and
after.

Nothing here is a substitute for the Lighthouse run: these harnesses give
*comparisons* and *byte counts*, Lighthouse gives the publishable field-style
metrics.

## Requirements

- Built output at `frontend/web/dist` (`cd frontend/web && bun run build`).
- The Playwright browser that `frontend/web` already installs:
  `cd frontend/web && bun run test:e2e:install`.
- **A writable `$HOME`.** This is not optional. Chrome writes its profile into
  `$HOME` and dies at startup with *"Failed to create headless user data
  directory container"* when `$HOME` is read-only — which is the case on many
  locked-down CI runners and inside the audit sandbox this was developed in.
  Every command below passes `HOME=/tmp`.

## Run

```bash
cd frontend/web

# 1. Baseline across mobile + desktop profiles (writes tests/performance/reports/)
HOME=/tmp NODE_PATH=$PWD/node_modules node ../../tests/performance/measure.cjs

# 2. A/B: shipped build vs a route-split prototype, measured interleaved
HOME=/tmp NODE_PATH=$PWD/node_modules node ../../tests/performance/ab-codesplit.cjs
```

Useful environment overrides:

| Variable | Effect |
|---|---|
| `PERF_DIST` | Directory to serve (default `frontend/web/dist`) |
| `PERF_OUT` | Report directory (default `tests/performance/reports`) |
| `PERF_LABEL` | Label recorded in the report (default `local`) |
| `PERF_SCENARIOS` | Comma-separated subset of the scenario names |
| `PERF_AB_RUNS` | Interleaved A/B pairs for `ab-codesplit.cjs` (default 3) |
| `PERF_HOME` | Browser `HOME` (default `/tmp`) |
| `PERF_CHROME` | Override the browser binary |

## What each file is

| File | Purpose |
|---|---|
| `measure.cjs` | Serves `frontend/web/dist` from a Vercel-shaped static server (brotli, immutable hashed assets, no-cache HTML, SPA rewrite) and measures FCP / LCP / CLS / TBT / main-thread busy / byte weight / DOM size under four profiles, using **applied** throttling over Chrome DevTools Protocol. |
| `ab-codesplit.cjs` | Builds a code-split prototype from a **scratch copy** of `frontend/web/src` (the real tree is never modified) and measures it **interleaved** against the shipped build, so machine drift cannot favour one arm. Also reports the deterministic eager-byte totals parsed from each `index.html`. |
| `reports/lighthouse-mobile-default.json` | Lighthouse 12.6.1 mobile result — the headline baseline (`score 0.26`). |
| `reports/latest.json` | Baseline from `measure.cjs`. |
| `reports/ab-codesplit.json` | A/B result from `ab-codesplit.cjs`. |

## Profiles

| Scenario | Viewport | CPU | Network |
|---|---|---|---|
| `mobile-slow4g-cold` | 412×915 @2.625 | 4× | 150 ms RTT, 1638.4 kbps down (Lighthouse mobile) |
| `mobile-4g-cold` | 412×915 @2.625 | 4× | 70 ms RTT, 9000 kbps down |
| `mobile-slow4g-warm` | 412×915 @2.625 | 4× | as Slow 4G, HTTP cache enabled across runs |
| `desktop-unthrottled` | 1350×940 | 1× | none |

## Three lessons baked into this harness

These cost real debugging time; they are recorded so the next person does not
repeat them.

1. **Only mapping-based sourcemap attribution is trustworthy for bundle
   analysis.** Grouping modules by the length of `sourcesContent` reported
   `simple-icons` as 41 % of the module graph, which would have justified
   replacing a package that costs the shipped bundle *nothing* — tree-shaking
   had already removed every unused icon. A sourcemap's `sources` array lists
   modules that were **loaded**, not modules that **emitted code**. Decode the
   `mappings` field and attribute generated bytes per segment instead
   (`ab-codesplit.cjs` and the plan's Appendix B show the technique).
2. **A warm-cache run needs one browser context, not one per run.** An HTTP
   cache lives in the context. An early revision created a context per run, so
   "warm" measured cold twice. The affected row in `latest.json` is flagged
   `invalid: true` — do not cite it.
3. **`networkidle` never fires here.** The app holds a SignalR connection, so
   the harness waits a fixed observation window after `load` instead. Anything
   that shortens that window will truncate LCP and CLS.

## Known limitations

- **Speed Index is not computed.** It needs a filmstrip, which CDP screencast
  cannot supply at a publishable fidelity. Lighthouse reports it; this harness
  does not, and it says so rather than guessing.
- **FCP/LCP capture is flaky under 4× CPU throttling in a container.** Chrome
  intermittently fails to render the page and logs `net::ERR_NETWORK_CHANGED`,
  yielding null paint entries. Byte counts, request counts and
  DOMContentLoaded are stable and are what the A/B trusts. **Re-confirm any
  user-visible timing claim with Lighthouse.**
- **Absolute numbers from a container are not production numbers.** Applied
  throttling in a sandbox is harsher than Lighthouse's simulated model, and the
  sandbox's outbound internet was measured at ~52 KB/s for third-party assets.
